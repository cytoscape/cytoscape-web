> in this repo. It is deliberately kept small.

> rejected, why a fix looks the way it does — live in `lessons-archive.md`.

## Coding Patterns

- [2026-10-20] A debounced "apply on change" timer must be cancelled by every path that applies at once. The FILTER tab's 300 ms auto-apply outlived the select/show radio's immediate apply and re-hid nodes after Select ▸ Show All (Firefox e2e flake in `select-menu.spec.ts`, 5 of 6 runs; Playwright's Firefox clicks land inside the window). The pending run lives per network in `src/data/filter/pendingAutoApply.ts`; Apply, the display-mode handler (`FilterTab.tsx`) and `showAll` cancel it.
- [2026-10-16] To detect that a network's nodes or edges changed, select `NetworkStore.topologyVersions.get(id)`, which every topology action bumps. Never use the `Network` object's identity (networks are mutated in place, so it never changes) or element counts (a replacement of as many elements as were removed leaves them equal). CyjsRenderer's full-render guard and trigger use the version (#861).
- [2026-10-16] `ViewModelStore.viewModels[networkId]` is a `NetworkView[]` (primary view first), never a single view. Type store-state snapshots with the store's real type, not `any`, and build test fixtures from real constructors (`ViewModelFn.createViewModel`) or real stores, so a wrong shape cannot agree with the code under test (#857; history in the archive).
- [2026-10-13] dnd-kit nested drop targets: never refuse a drop by passing `disabled` to `useDroppable`. A disabled droppable leaves collision detection, so the pointer falls through to the target it is nested in (a filter condition released over its own row was appended to its enclosing group). Keep every target registered, mask its highlight, and make the drop a no-op in the handler (`ConditionDnd.tsx` + `canDropCondition`). Keyboard drags have no pointer: apply the same innermost-target rule at the dragged card's center rather than `closestCenter`, which can pick an enclosing group.
- [2026-10-12] Dexie schema: never add a store to a `currentVersion` that has run anywhere, your own localhost:5500 database included. Dexie 3 does not create it; it only warns "Schema was extended without increasing the number passed to db.version()", and every write to the store then fails. Bump the version. A test for it must seed the old schema AFTER `deleteDb()` + `closeDb()` + `Dexie.delete(DB_NAME)`: `deleteDb()` reopens the app's database at the full current schema, which hides the bug (see the v13 → v14 test in `db.test.ts`).
- [2026-03-04] enableMapSet: Any new standalone test entry point MUST call `enableMapSet()` before Immer can handle Map/Set — omitting it causes cryptic test failures.
- [2026-03-04] App API: Core functions in `src/app-api/core/` must have zero React imports. Use `useXxxStore.getState()` instead of hooks.
- [2026-03-04] App API: All public API functions must return `ApiResult<T>` — never throw across the API boundary.
- [2026-09-29] A removed App API field is still INPUT: `CyApp.components` is gone from the types (#786, api-types 1.0.0-beta.5), but an app bundle is untyped at runtime and an app record saved by an older host still has it. Anything that puts a `CyApp` into `AppStore` goes through `toStoredApp` (`appStoreImpl.ts`), which drops `components` together with `resources` — both can hold `React.lazy` refs, which crash React once Immer freezes them. `loadRemoteApp` warns when a bundle still declares the field. When removing a field from a public type, grep the zod schemas in `src/data/db/validator.ts` too: `CyAppSchema` REQUIRED `components`, so every record written after the removal would have failed read-path validation.
- [2026-03-04] Serialization: Before saving to IndexedDB, proxy objects must be converted with `toPlainObject()`. Map-based data needs specialized serializers.
- [2026-07-25] Dexie transaction scope: Inside `db.transaction('rw', db.someTable, ...)`, calling a helper that reads a DIFFERENT table throws `NotFoundError`. Keep a raw in-scope reader separate from the public getter that joins across tables.
- [2026-07-25] Per-tab state: Keep per-tab state OUT of shared IndexedDB rows rather than filtering it on read. Masking on hydration is not enough — the next local mutation writes the tab's private value back into the shared row, and a newly opened tab inherits whatever tab wrote last.
- [2026-07-25] PanelState has four values (OPEN, CLOSED, HIDDEN, MINIMIZED). Validating against only OPEN/CLOSED silently resets hidden or minimized panels.
- [2026-08-31] The Immer freeze reaches app code through the App API: `appData.get()` returns `local[key]` straight out of `AppDataStore`, so a plugin receives the host's DEEPLY FROZEN object, not a copy. The MCODE app crashed its own panel on the first restored cluster (`Cannot assign to read only property 'nodePositions'` in its thumbnail render) — surfaced only as the host's "Plugin unavailable" fallback, because `PluginErrorBoundary` replaces the panel and hides the error. Apps must copy before mutating what they read; the contract is now on `AppDataApi.get`, in `api_docs/Api.md`, and asserted in `AppDataStore.spec.ts`. Any future API that returns a store-held object inherits this — return a copy or document the freeze.
- [2026-08-11] Store objects are Immer-frozen — check add() for param mutation before re-feeding them: `setAutoFreeze` is never disabled, so anything read back out of a store is deeply frozen. `ViewModelStore.add` mutates the view it is given (viewId/type defaults, selection carry-over), so any path that hands store-held objects back into an add (e.g. the #665 in-memory cache-miss fallback) must pass shallow copies or it throws `Cannot assign to read only property`. Audit each add() for parameter mutation when building such a path.
- [2026-08-11] In-memory store fallback must never shadow a successful DB read: cross-tab sync (`SyncTabs.tsx`) deliberately leaves non-current networks stale in the stores and relies on the network swap re-reading IndexedDB. A memory-first load would resurrect stale copies across tabs; consult memory only on a DB cache miss (see `useLoadCyNetwork` + `getCyNetworkFromStores`).
- [2026-08-12] `Network` is a live view, not a snapshot: `NetworkImpl.nodes`/`.edges` are **getters** over the underlying Cytoscape store, and `NetworkFn.addEdge`/`addNode` mutate that store in place and return the *same* object. So the `networks` Map a React hook captured is stale only as a *Map* — the `Network` it holds keeps reporting current counts. `createEdgesCore` assumed the opposite and did `network.edges.length + edgeIds.length` after calling `addEdge`, double-counting every new edge in the workspace panel summary (`E: 3` for 2 real edges; the inflation scaled with batch size). Capture counts BEFORE mutating, like `deleteEdgesCore` does. A unit test that mocks `addEdge` cannot catch this — the mock leaves topology untouched, so the buggy arithmetic looks right; test summary bookkeeping against the real store. **`createNodesCore` had the identical bug** (`network.nodes.length + nodeIds.length`), fixed the same way; both are now covered by `*.store.spec.ts` files. Its symptom read differently — "+2 on the first node, +1 after" — because the buggy formula yields `real + 1` on *every* call, so only the first add visibly jumps, and a correct `deleteNodesCore` silently resets the drift. Both delete paths were already correct. To confirm there is no third site, grep `nodeCount:`/`edgeCount:` for `.length + `: every other summary write is a plain live read, which is correct *because* the getter is live.
- [2026-08-25] UiStateStore persists by hand, so a raw `setState` on it is a silent data loss: the store has no persist middleware — each setter calls `persistUiState` itself, and `useUiStateStore.setState(...)` calls none of them. `tableApi` used a raw `setState` to add App-API-created columns to `tableDisplayConfiguration`, so the column vanished from the Table Browser on reload unless an unrelated setter happened to flush the whole `ui` row first (#685). Always go through a store setter. The `ui` row write is now on the 300 ms coalescer (`persistenceScheduler`, key `UiState`), which is what made the persisting setters cheap enough to call from `page.evaluate()` and removed the `setTimeout(0)` wrappers the bypass needed. Its `scheduleWrite` callback must read `useUiStateStore.getState().ui` at flush time — the `ui` argument is derived from the Immer draft and its proxies are revoked when the producer returns.
- [2026-08-25] A network load overwrites App API writes to `visualStyleOptions`: `loadCurrentNetworkById` (`WorkspaceEditor.tsx`) opens with `setVisualStyleOptions(networkId, <the copy read from IndexedDB>)`, which persists. Anything written through the App API while a load is still in flight is silently replaced by the stale DB copy. A CX2 file import runs that load a second time, so the window is real: on WebKit it landed ~200 ms after a `CyWebApi.table.createColumn` and wiped the new column's display-config entry every run. E2E specs must drive the App API from a reloaded, quiet page, and wait for the node table to have rows before touching it. Reloading is itself gated on durability — `getCyNetworkFromDb` throws `CyNetworkCacheMissError` unless `cyNetworks`, `cyTables`, `cyVisualStyles` and `cyNetworkViews` all have the row, and reloading early leaves the app with an empty store (#665).
- [2026-08-25] Coalesced writes read state at flush time, so an unpersisted raw mutation can ride along on someone else's write: `persistUiState` schedules a callback that reads `useUiStateStore.getState().ui` when it fires. A store mutation made by a raw `setState` in between is therefore picked up by any write already queued. Consequence when bisecting: reverting only `tableApi.ts` to reproduce #685 does NOT reproduce it — the raw `setState` piggybacks on the pending `UiState` write and the column persists anyway. Revert `UiStateStore.ts` and `persistenceScheduler.ts` too.
- [2026-07-28] Shared defaults by reference: `applyTabViewState` spread `panels: tabState.panels`, so passing `DEFAULT_TAB_VIEW_STATE` (its own fallback, and what `withoutTabViewState` passes) handed callers the module-level default itself. The boot's URL overlay then assigned into it and rewrote the default for the session — a wrong panel state for every later read. Copy any object taken from a module-level default before returning it.
- [2026-09-21] Only SOME UiStateStore setters persist: `setPanelState`, `setActiveTableBrowserIndex`, `setActiveNetworkBrowserPanelIndex` and `setNetworkViewTabIndex` update the store and write nothing — neither the `ui` row nor the per-tab sessionStorage state (`saveTabViewState` runs only inside `persistUiState`, which those four never call; the table browser's tab change persists only because it goes through `setUi`). So an open/closed pane or a selected tab survives a reload only if some persisting setter happens to run afterwards. The App API's `panel.open` uses these setters on purpose — it behaves exactly like the click it stands in for — but do not read "goes through a setter" as "is persisted" (the Panel API plan first claimed it was). Also: the right pane's selected tab lives in the non-persisted `SidePanelStore`, not in `SidePanel`, because the component is unmounted while the pane is closed.
- [2026-09-03] `networkModified` has ONE choke point: `markNetworkModified(networkId)` in `src/app-api/core/undo.ts`, called from `corePostEdit` and from `useUndoStack.postEdit` (and from undo/redo replay). Any new mutation path gets the flag for free IF it records an undo entry; a path that records none must call `setNetworkModified` itself and say why in a comment (the surviving sites: table sort/move/resize/duplicate/insert-column, the Vizmapper lock checkboxes, style duplicate/rename/delete, the table-file join, service-app `updateNetwork`). The two WorkspaceEditor subscriptions that used to do this are gone (#680) — they leaked a listener per render and keyed on `currentNetworkId`, so app API writes to any other resident network were never marked.
- [2026-09-03] `tableImpl.applyValueToElements` branches on `elementIds != null`: OMITTING the argument applies to every row, but passing `[]` applies to NONE. Anything that snapshots the affected rows (an undo entry, a modified flag) must treat the two cases differently — `elementIds.length > 0 ? elementIds : allRows` silently records every row for a write that changes nothing.
- [2026-09-03] App dialogs have ONE chrome: `features/AppManager/AppDialogShell.tsx` (CyDialog + structural Close "X" + Escape handler + AppIdProvider + PluginErrorBoundary + Suspense) is rendered by both `ModalLauncherHost` ('modal-launcher' resources) and `AppDialogHost` (`apis.dialog.open`). A new host surface for app-supplied dialog content must go through the shell, not a fresh `<Dialog>` — the dismiss policy and the visible-exit guarantee live there. App dialogs are the policy's ONE documented Escape exception (requested by Christian), so they are deliberately NOT rows in `dialog-dismiss.spec.ts`. `'apps-menu'` resources are plain data (label/tooltip/icon URI/onClick/isEnabled) that `AppMenu` renders itself; never reintroduce a `component` field on that slot, and `icon` is a URI like the search-bar's, not SVG path data. Both slots render that URI through `components/UriIcon.tsx` — SVG (`data:image/svg+xml` or `.svg` path) as a CSS mask in `currentColor` so it follows the theme, raster as an unchanged `<img>` (masking raster logos looked bad) — never bypass it with a raw `<img>`.
- [2026-08-31] Suspense reveal desyncs allotment: key allotment layouts with `useRemountKeyOnReveal` (`src/data/hooks/`), and never render an app-provided or `React.lazy` component without a local `<Suspense>` — an unguarded one suspends to the app-level boundary, and the hide/reveal corrupts allotment's split-view state (`Index out of bounds` on the next pane unmount; #696, details in the archive). Also: `features/Error.tsx` shadows the global `Error` constructor — instanceof checks there must use `globalThis.Error`.
- [2026-09-21] Always-mounted dialogs keep their `useState` seeds: a dialog whose parent only toggles `open` (e.g. `AnalysisMenu` → `LLMQueryOptionsDialog`) runs its initializers once, so edits abandoned with Cancel reappear on reopen. Re-key the dialog on the closed→open edge from a thin wrapper (adjust-state-during-render, no effect). Do NOT fix it by moving the body into a child component rendered inside `<CyDialog>`: `src/components/dialogPolicy.test.ts` scans each `<CyDialog>…</CyDialog>` block lexically for a Cancel/Close control and fails when the button lives in another component.
- [2026-09-16] MUI `Autocomplete` with `freeSolo`: control ONLY `inputValue`, never `value` and `inputValue` with the same string. Setting `value` on every keystroke marks the input pristine, so the list never filters and the popper stays open over the dialog's buttons (Playwright then reports the listbox "intercepts pointer events" on Confirm). The typed text is the model/name; see `LLMQueryOptionsDialog.tsx`.
- [2026-09-03] MUI `Popper`/`Portal` content mounts ONE render after `open` flips true: `Portal` resolves its container in a layout effect and only then renders the portal, so a parent effect keyed on `open` that does `document.getElementById(menuId)` finds nothing. Put mount-time work (focus, measuring) in an effect INSIDE the portal content, and pass it what it needs as props computed in the same render that opened it (the toolbar `MenuBar` keeps the open intent in state next to `openId` for exactly this).
- [2026-09-29] No toolbar menu row renders a dialog (#784): a row unmounts with its menu, and a dialog inside it (a React child in its own DOM portal) forced `DropdownMenu` to guess from focus, click and key events whether it still belonged to the menu. Every guess eventually failed (clicks into fields, Confirm, a Select opened and dismissed) and unmounted the dialog. The menu component owns the dialog; the row's `onClick` closes the menu, then opens it (`HelpMenu`, `DataMenu`, `ToolsMenu`). `menuRowDialogs.test.ts` enforces it, and `DropdownMenu` no longer tolerates row dialogs at all. A flow that opens its dialog after async work lives in a hook the menu calls (`useSaveNetworkToNDExFlow` → `{ start, dialogs }`) reading stores via `getState()` at run time; a hoisted dialog either re-keys on open (`ExportImage`) or mounts only while open when it subscribes to the whole workspace (`WorkspaceNamingDialog`, `MergeNetworkDialogHost`). Check hoisted dialogs for a close that only happened through the row's unmount — the HCX save warning never closed itself on submit. `DropdownMenu` still decides focus-out in a task (a press on the open trigger has a microtask checkpoint between focusout and focusin) and click-away on mousedown (a press released elsewhere fires its click on `<body>`). Unit tests of either must model the native order: `blur()`, `await Promise.resolve()`, `focus()`.
- [2026-09-03] MUI `Popover` is a modal with an invisible full-screen backdrop: while one is open every other click on the page only closes it. Use it for a single detached surface, never for a set of sibling triggers (menubar, tab strip) — those need a non-modal `Popper` + `ClickAwayListener` and shared open state (`src/features/ToolBar/MenuBar.tsx`). Also: a keydown inside a portaled submenu bubbles through the React tree to every ancestor level's handler, so each handled key must `stopPropagation()` or the parent level acts on it too.

- [2026-09-29] MUI `Snackbar` can call `onClose(null, 'timeout')` after it has closed: it stays mounted (rendering `null`) after the exit, a mouse-leave or blur on it during the exit transition restarts its auto-hide timer, and nothing clears that timer. `SnackbarMessageList` advanced its queue index on every `onClose`, so closing a message with its X and moving the pointer away skipped the next message. A close handler must act only on the message on screen (idempotent dismiss), ignore `timeout` when the current message has no `autoHideDuration`, and advance a queue in `TransitionProps.onExited`, not in `onClose`.

- [2026-09-23] `cy.resize()` clears the canvases synchronously (`matchCanvasSize` sets `canvas.width`) but Cytoscape.js redraws only on its next rAF, and ResizeObserver callbacks run AFTER that frame's rAF and before paint. Calling `cy.resize()` from a ResizeObserver therefore paints a blank canvas every drag step (flicker); follow it with a synchronous `cy.renderer().render()` (`forceRender()` only schedules a frame). See `useCenterAnchoredResize.ts`.

- [2026-09-23] CyjsRenderer reuses ONE Cytoscape.js instance for every network, and `cy.removeAllListeners()` does not cancel a lodash-debounced call already scheduled. A debounced handler that reads the camera or elements from `cy` and writes under a closed-over network id must be flushed before `renderNetwork` swaps networks (and before destroy), or it saves the next network's state under the previous id — this is how a quick pan-then-switch restored the other network's viewport (`flushPendingViewportSave`, `viewport-network-switch.spec.ts`).

- [2026-09-23] Cytoscape.js calls `cy.resize()` on ITSELF (debounced 100 ms) from its own ResizeObserver, window `resize` and a container-`style` MutationObserver, and a debounce timer can run before the next rendering frame delivers our ResizeObserver callback. Any logic keyed to size changes must therefore hook `cy.resize` itself, not only observe the container — `useCenterAnchoredResize` wraps the instance's `resize` for that reason. Measure against `cy.width()/height()` (the size the pan is relative to), not an observer's previous reading. Also: while the Browser pane is hidden the page lays out at bogus sizes (a 30 px centre pane) and runs no ResizeObserver callbacks — discard measurements taken with `document.visibilityState === 'hidden'`.

- [2026-09-24] Cell View (`CirclePackingPanel`) zoom state lives in d3 only (`svg.__zoom`). It used to be mirrored in a React `transform` state that an effect re-applied after render, which put a stale transform back over any change made in between; never reintroduce a React copy. A layout rebuild must reuse the size the existing layout was built for (root at `(w/2, h/2)` → `(2·root.x, 2·root.y)`): `NetworkTabs` measures `boxSize` once on mount, before a network switch has reopened the right panel, so the measured size is not reliable.
- [2026-09-24] 'Without the fix' e2e comparisons against the dev server (`E2E_DEV=1`): after swapping a source file, confirm the served module changed (`curl -s localhost:5500/<path> | grep <marker>`) before running — Vite's watcher can lag, and both runs then test the same code.

- [2026-09-25] Keycloak `tokenParsed.preferred_username` is NOT the NDEx account name. Keycloak sets it (often copied from the upstream IdP, e.g. a campus SSO login), and NDEx keeps its own `userName`. The Load from NDEx "Only mine" filter sent the Keycloak name as `accountName` and always got zero results (#760). Wherever NDEx expects an account name, use `fetchNdexUserName` (`src/data/external-api/ndex/user.ts`, ndex-client `user.getCurrentUser()`), never the token claim. Display-only use (`LoginPanel`) is fine.
- [2026-09-25] Per-view actions must name their view's network: the Hierarchy Viewer's TREE VIEW and SUB NETWORK VIEWER share the `cyjs` renderer and register renderer functions per network id, so a toolbar button that resolves its network from `ui.activeNetworkView` acts on whichever view was clicked last, not the one it sits in (#762). Pass the view's own network down (`FloatingToolBar`'s `viewNetworkId`). The fallback to the active view is still right for the Share button, which relies on it on purpose (#758).

- [2026-09-25] Find opaque aspects by key presence, not truthiness: `otherAspects.find((a) => a[TAG])` skips a present but falsy value (`"filterWidgets": null`, `false`, `0`, `""`), so the malformed aspect never reaches its validator and nothing is logged (#770 review). Use `Object.hasOwn(aspect, TAG)` and hand the raw value to validation, as `findFilterAspect` (`src/features/HierarchyViewer/utils/getFilterAspect.ts`) does.
- [2026-09-26] The Hierarchy Viewer filter owns the visibility bypass: `CheckboxFilter` replaces the `NodeVisibility`/`EdgeVisibility` bypass map of its target network when it applies, and deletes the bypass for every row of its table (the subnetwork's full node or edge table) when disabled (#769). Do not make it merge with, or preserve, other writers' visibility bypasses: "filter off" or "all checked" must reliably show every element, or a leftover hidden element looks like a bug or quietly skews an analysis. Do not track in the component what it applied, either: it unmounts on every subsystem switch while the bypass stays in the store, so a filter mounted disabled must still clear an earlier mount's bypass. A second writer of visibility would need per-writer layers; wait for a concrete use case (#771 review).
- [2026-09-26] Hierarchy Viewer UI state must outlive the side panel: the right panel closes whenever a non-hierarchy network is selected (`useHierarchyViewerManager`), which unmounts `MainPanel` and `FilterPanel` together, so React state in either resets on every network switch; hoisting it from `FilterPanel` into `MainPanel` (#766) only survived subsystem switches (#772). Keep such state in a store keyed by the subnetwork: the filter's on/off switch is `FilterConfig.enabled` (undefined means on, falling back to the `filterEnabled` URL param), set with `FilterStore.setFilterEnabled`. Also: `FilterPanel`'s `searchParams.set(...)` calls never reach the URL (`setSearchParams` is commented out), so URL params are read-only seeds. Since #774, filter configs are restored at startup (see the next rule).
- [2026-09-26] Restoring filter configs (#774): `loadWorkspaceState` hands the `filters` rows (validated by `getAllFilterConfigsFromDb`) to `FilterStore.hydrate`, which keeps a config only when a workspace network owns it — name `N` or `N_…`, since a subnetwork id is `<networkId>_<subsystemNodeId>` — and deletes every other row, including the unread `checkboxFilter` default (#775). The saved row is NOT the config the user sees: `SubNetworkPanel` rebuilds it from the `filterWidgets` aspect on every subsystem load, so route new state through `registerFilterConfig` → `restoreFilterState`, which carries over only the checked values still in the table and `enabled`, and only while attribute and target are unchanged. Match saved range values by content and keep the FRESH value: rows cross IndexedDB as copies, while `CheckboxFilter` matches row values against the range by identity, so a structurally equal copy hides every row (#776 review; list-valued attributes are otherwise unsupported, #777). Anything that deletes a network must go through `deleteNetworkFromAllStores`, which now drops its filter configs by prefix; a mocked FilterStore in a cascade test needs the new actions (`networkApi.test.ts`).

- [2026-09-29] An effect that mirrors a store flag into another setting must act on CHANGES of the flag, not on the value it mounts with. `useHierarchyViewerManager` mapped `enablePopup` (default `false`) to the right panel on mount too, so every boot with a regular network closed the panel ~170 ms after `?right=open` (or a restored open panel) had opened it. `app-data-panel.spec.ts` checked the open button once and flaked whenever the close landed after the check (every run against the dev server). It now keeps the last value in a ref and returns when it is unchanged. When a spec flakes on "panel/element not found", log the store transitions with timestamps before touching the test.
- [2026-09-28] A Cytoscape.js pan only means something relative to a canvas size. A viewport restored into a hidden (0 x 0) canvas — a hierarchy's Tree View while its Cell View tab is selected — cannot be adjusted yet, so the restore must declare the saved size with `setPanReferenceSize(cy, size)`, and a save must record `panReferenceSize(cy)` (the last visible size while hidden), never omit the size. Both live in `useCenterAnchoredResize.ts`, per instance.

- [2026-09-30] The URL is the ONLY network-load trigger: `WorkspaceEditor`'s swap effect is keyed on `params.networkId`, and nothing syncs `currentNetworkId` back into the URL. A path that removes the current network without navigating leaves its id in the URL, so re-adding the same network later navigates to an unchanged path (`urlManager` also skips it outright) and it never loads — "Loading network data..." forever. `deleteAllNetworks` had exactly this bug after Remove All → Open Sample Networks; it now navigates to `/<ws>/networks`. The App API's deletes (no router in core) had it too; removals are now covered in one place, `useUrlFollowsNetworkRemoval` in `WorkspaceEditor`, which moves the URL off a network the moment it leaves `networkIds` — a new removal path needs no navigation of its own. Only removals: an App API `switchCurrentNetwork` still leaves the URL alone. Also: `urlManager` silently drops any navigation within 300 ms of the previous one, so an e2e that re-navigates right after one (instant route mocks) must wait that window out, and a listener that navigates must retry after it (the hook does).

- [2026-10-15] A tab on `/manual/*` opens `cyweb-manual-db`, not `cyweb-db` (`src/data/db/dbScope.ts`, #839), and the scope is fixed at page load. Never move between the manual and the editor with `navigate()` — use a full page load — and in e2e, read the manual's rows from `cyweb-manual-db`. Manual pages are MDX: `content.test.ts` checks links, anchors, images and `sources` globs, so run it after renaming a feature file a page names.
- [2026-10-15] Never call Cytoscape.js `ele.show()` / `ele.hide()` (or `ele.style('display', …)`) in the renderer. Visibility comes from the visual style's `display` through `cy.style(...)`, and an element-level `display` overrides the stylesheet until removed, so the store and the canvas disagree. The selection sync called `show()` on every store-driven selection change (a leftover from the old selection-based Hierarchy Viewer filter), so Select All / Deselect All from the menu re-showed hidden elements (#834). Canvas clicks were spared only because the sync returns early when Cytoscape.js already has the selection, which hid the bug. Selection sync is now `syncCySelection.ts`, tested on a headless instance.

## Build & CI

- [2026-08-28] npm comment keys: A `"//foo": [...]` comment key INSIDE a `dependencies`/`devDependencies` block makes `npm install` fail with "must provide string spec" — dependency values must be strings. Put comment arrays at the package.json top level (the psicquic-cw `"//devDependencies"` convention).
- [2026-10-05] npm publishes are asynchronous: a version can stay E404 on `npm view` for minutes after `npm publish` succeeds. If the api-types release fails in **Verify the registry**, never touch the tag — wait until `npm view` shows the version, then re-run against the tag with `dry_run=false` and the same `dist_tag`; it resumes with `action=skip`. Re-running earlier tries to publish again. History in lessons-archive.md.

- [2026-03-04] Import sorting: Import sorting is no longer lint-enforced after the oxlint migration; keep imports sorted by convention.
- [2026-03-04] No `console.log`: Production builds strip direct `console.*()` calls through Vite's Oxc minifier. Use the `debug` logger from `src/debug.ts`.

## Testing
- [2026-10-21] A headless Cytoscape.js test that gives nodes `position`s must pass `layout: { name: 'preset' }`. The default is the `null` layout, which moves every node to the origin and makes the given positions silently ignored (`nodeDragUndo.test.ts`). Cytoscape.js emits `grab` and `dragfree` once per node of a dragged selection, so `nodes.emit('dragfree')` on a collection reproduces a group drag headlessly.
- [2026-10-20] E2E: a network made with `CyWebApi.network.createNetworkFromEdgeList` has EVERY node at the origin, so a click or right-click aimed at one node lands on whichever is drawn on top. A test that cared which node it hit failed for the wrong reason (the context menu took the top node). Spread the nodes with `viewport.updateNodePositions` first (`seedNetwork` in `delete-selection-shortcut.spec.ts`), and check the clicked node when the test depends on it.
- [2026-10-20] E2E against your own `vite preview` (port 5501): a preview left over from an earlier run (another build, another worktree) keeps the port, so the new `--strictPort` one exits silently and every spec tests the OLD build — new shortcuts all "failed" while menu specs passed. Before a run, check `lsof -nP -iTCP:5501 -sTCP:LISTEN` is empty, then confirm the served bundle has your change (`grep -l <marker> dist/assets/*.js`, and `curl` the page).
- [2026-10-16] E2E on a `loading="lazy"` image: Firefox fetches it only near the viewport, so `naturalWidth` stays 0 for an image below the fold while Chromium and WebKit load it early. `scrollIntoViewIfNeeded()` before asserting it loaded.
- [2026-10-16] Never hand a Cytoscape.js collection or element to a Vitest matcher (`expect(cy.nodes()).toHaveLength(2)`, `expect(ele).toBe(other)`). When it fails, Vitest pretty-prints the value, which references the whole instance, and the worker dies with a heap OOM instead of reporting the failure. Assert on plain values (`cy.nodes().length`, `ele === other`). To mount CyjsRenderer in jsdom, wrap the `cytoscape` factory to create headless instances (`CyjsRenderer.spec.tsx`).
- [2026-10-16] E2E that needs your own build while port 5500 is busy (the user's dev server): `E2E_DEV=1` reuses that server, so it tests THEIR checkout, not yours — fine for proving a spec fails without the fix, useless for proving it passes. Build, serve with `npx vite preview --port 5501 --strictPort`, and run `CYWEB_HOST_URL=http://localhost:5501 npm run e2e:spec:run -- <spec>`; this skips the webServer (and the remote-app fixture), so it only suits specs that need neither Keycloak nor the fixture remote. Under `E2E_DEV=1` a spec can also `await import('/src/data/hooks/stores/XxxStore.ts')` inside `page.evaluate` to read the app's own store instance — debugging only, a preview build has no such path.
- [2026-10-15] Platform detection in Playwright: on macOS, Playwright's Chromium reports `navigator.userAgentData.platform` as "Windows" while `navigator.platform` is "MacIntel" and `ControlOrMeta` presses Meta. A shortcut that trusted `userAgentData` waited for Ctrl and never fired in e2e, though real Chrome worked. Don't gate a keyboard shortcut's behavior on platform detection: accept Ctrl or ⌘ and use the platform only for the label (`useSelectAllShortcut.ts`).
- [2026-10-13] E2E after clicking an MUI `Menu` item: the menu fades out still covering the page, but it is already `aria-hidden`, so `getByRole('menu')` reports it gone while a `mouse.down` lands on its items. Wait for `getByRole('menu', { includeHidden: true })` to have count 0 before pointer actions on what it covers.
- [2026-10-13] E2E drags (dnd-kit): never release (`mouse.up`, `touchEnd`, Space) right after the move that reaches the target. dnd-kit publishes `over` from a passive effect one render behind the pointer, and the drop goes to the stale target; WebKit hits it every time when an 8px gap is entered only on the last step. Wait for the target's `data-drop-over="true"` first (`expectDropOver` in `filter-tab.spec.ts`). Keyboard drags: scroll the pane to its top before picking up, because the arrow keys smooth-scroll it first and a pick-up mid-scroll lands a gap off.
- [2026-10-13] E2E drags (dnd-kit): hovering near the edge of a scroll container auto-scrolls it, which moves the target out from under the pointer. Scroll the container to a known position before measuring targets. For touch drags, `Emulation.setTouchEmulationEnabled` + `Input.dispatchTouchEvent` on a CDP session (Chromium only) produce real touch pointer events (see `filter-tab.spec.ts`).
- [2026-09-30] `NetworkSummaryStore.addAll` never writes IndexedDB (only `add` and `update` do). Its callers are the boot step `publishWorkspace` (rows it just read) and Open Sample Networks (`useLoadDemoNetworks`, via a hook alias `addSummaries`), so a sample's summary has NO `summaries` row until something `update`s it; boot refetches any missing summary from NDEx (`loadNetworkSummaries`). An e2e that proves a delete by probing the `summaries` row therefore times out before the delete even runs. Assert on what persists (the workspace row's `networkIds`, via a reload) instead.

- [2026-09-28] A message snackbar that covers a click target never hides on its own during the click: MUI pauses `autoHideDuration` while the pointer is over it, and Playwright's actionability retries keep the pointer there, so the click times out after 60 s instead of waiting 5 s. `SnackbarMessageList` now sits bottom-center (#782) — it used to cover the network tab strip (Firefox flake in `hierarchy-cell-view.spec.ts`). If a spec must click under it (table rows, the cookie-consent banner), close the message through its Alert's Close button (scoped to `snackbar-message-list`, `exact: true`) and assert it hidden first; never `force` the click.

- [2026-09-22] An outlined MUI `TextField` renders its own `<legend>` (the notched outline), so `fieldset.locator('legend')` is a Playwright strict-mode violation once a text field sits inside a form fieldset — use `.first()` or the legend's text. Likewise `getByRole('combobox')` is ambiguous in any dialog that also renders a `dropDown` parameter; the Layout Settings selector carries `data-testid="layout-selector-combobox"` for that reason.
- [2026-09-03] `vi.clearAllMocks()` clears calls, NOT implementations: a `mockImplementation(() => { throw ... })` set by one test leaks into every later test in the file, and a new `describe` block appended at the end of a long spec inherits it (cost an hour on `viewportApi.test.ts`). Reset the specific mock in the block's own `beforeEach`.
- [2026-08-03] jsdom drops CSS values it cannot parse: `getComputedStyle` returns `auto` for `width: min(500px, calc(100% - 32px))` while `calc(100% - 32px)` resolves fine. Layout-assertion unit tests must stick to values jsdom's cssstyle understands, or assert in Playwright instead.
- [2026-09-03] MUI Popover rows outlive the close by a tick: `DropdownMenu` closes with `transitionDuration={0}`, but the Popover still unmounts its children only after the exit transition settles, so a unit test asserting a menu row is gone right after `fireEvent.click` must `waitFor` it (see `AppMenu.spec.tsx`).
- [2026-08-26] Playwright `getByRole` name matching is SUBSTRING by default: `getByRole('button', { name: 'Close' })` also matches the side panel's "Close panel" button, so `.last().click()` closed the panel the test needed open instead of the dialog. Close dialogs by their `data-testid` (e.g. `app-settings-dialog-close-button`), or pass `{ exact: true }`.
- [2026-08-26] E2E: an app-api `switchCurrentNetwork` does NOT move the address bar, and boot resolves the current network from the URL first (`resolveInitialNetworkId`). A test that switches through the API and then reloads `page.url()` comes back on the OLD network. Rebuild the path with the intended network id (anchor on the `networks` segment — a based deployment prefixes it). Likewise, do not assume `?import=` order decides which network boot leaves current.
- [2026-08-28] Allotment.Pane drops unknown props: `data-testid` on `<Allotment.Pane>` (and the `<Allotment>` root) never reaches the DOM — the component only forwards its declared props. The pane testids in `WorkspaceEditor.tsx` are inert; Playwright must target content INSIDE the pane (e.g. `side-panel`) instead.
- [2026-08-25] MUI dialog dismissal: `stopPropagation()` on a `<Dialog>`'s own `onClick`/`onKeyDown` blocks NEITHER backdrop click nor Escape — MUI runs the user handler first and dismisses regardless. A paired `preventDefault()` DOES break typing inside the dialog. `disableEscapeKeyDown={false}` is the default and does nothing. Modals now close by button only: render through `CyDialog` (`src/components/CyDialog.tsx`), and every dialog needs a visible Cancel/Close or the user is trapped. See `docs/specifications/DIALOG_DISMISS_POLICY.md`.
- [2026-08-28] modal-launcher content must not treat unmount as "closed": the host runs under React.StrictMode, whose dev double-mount runs every effect cleanup once right after mount — a `useEffect(() => () => discardPayload(), [])` in a modal component fires while the modal is open and blanks it (empty CyDialog paper over a backdrop; bit psicquic's SelectDatabasesDialog). Close side effects go on the closing buttons; reopening self-heals by rewriting the payload before each openModal(). Documented in Api.md's registerModal section.

- [2026-08-28] Allotment drops unknown props: `Allotment`/`Allotment.Pane` forward only their declared props (children, className, minSize, maxSize, preferredSize, priority, snap, visible) — a `data-testid` on them never reaches the DOM (the library even hardcodes `data-testid="split-view-view"` on pane containers). Put test ids on a real element (wrapper Box) inside the pane; a Playwright wait on a pane-level testid otherwise times out, and the onboarding-tour anchor spec's source-literal fallback will NOT catch the dead attribute.
- [2026-09-30] Manual Hierarchy Viewer checks in the browser pane: `CyWebApi.network.createNetworkFromCx2` does NOT make an HCX file a hierarchy ("This network is not a hierarchy").
